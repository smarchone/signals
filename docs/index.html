tl;drDon't micromanage your agent, and don't let it run wild.
Steer the big calls: /signals ctx loads them, and nothing new lands without your OK.

The problem
  • The code keeps the what. The why gets lost in sessions, prompts and stale specs.
  • Agents either run wild or get micromanaged, and that eats your attention.
  • No shared mental model of what's decided, for you, your team or your agent.
What are you steering?know more →
  • Sessions → none of them knows what the others decided.
  • Prompts → you re-steer the same calls, or micromanage every step.
  • Specs → stale by build two. The why gets lost. Back to prompting.
  • Decisions → signals. One shared model of what's decided, steering every build.
One owner

Every call has a role.

CEO owns why, PM what, Architect how. Each call routes to its owner.

You're the board

Conflicts are yours.

The agent proposes, you decide. Nothing is auto‑resolved.

Plain markdown

It lives in your repo.

Reviewed in git, read by any agent. Big calls only, not a spec.

Get started · ~1 min · needs a coding agent with skills

$ npx skills add smarchone/signals -g   # for all your projects

› /signals ctx "add password reset"     # load the decisions it touches
› /signals update                       # review what the session settled
